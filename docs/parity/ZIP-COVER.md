## 这张表覆盖什么、不覆盖什么

**覆盖**：

1. 封面设置页 `CoverConfigScreen.kt` 的 **18 个设置项** + 5 个分组标题（A 块）。分组标题本身不单独成行——它们是 18 项的分组容器，标题文案写在所属首行的「差异说明」里，与上游 `SplicedColumnGroup` 的五个 `title` 一一对应。
2. 默认封面相册整条链路（B 块）：选择 sheet 的「无」项与相册项、管理页的空态/新建/改名/删除、编辑器的日夜间 tab/添加图片/删除单图，以及支撑它们的数据层（落盘位置、`albums.json`、三个选择键、迁移）。
3. 封面规则 sheet 的 5 个可见单元 + 规则求值链路 + `coverRule.json` 的备份归属（C 块）。
4. 封面渲染管线（D 块）：`CoilBookCover.kt` 的文字层与图片层、`BookshelfCover.kt`、`CoverBlurBackdrop.kt`、`CoverImageView.kt`、`BookCover.kt` 的取图入口、`BookshelfCoverPreloader.kt`。这一块单独立行，因为 [盘点规约](../PARITY-RULES.md) 第五节明确「渲染与公共管线不属于任何类别」。
5. `coverConfig` 在 ZIP 里的归属与门控（E 块）：14 个 `coverPrefKeys`、4 个不在 14 键里的字段、`coverRule.json`、相册目录。

**不覆盖**（各自的表在哪里）：

- **书架卡片上的角标与进度**（未读章节数、更新小红点、更新中进度条、书籍类型标签、左下角来源文字）：这些是 `BookshelfCover.kt` 的 `badgeText`/`showBadgeDot`/`leftBottomText`/`isUpdating` 参数，但驱动它们的数据是书籍状态而不是封面设置，界面上属于书架卡片本体。归 [书架对照表](BOOKSHELF.md) A1 块（该表 :118-121 已逐条盘过）。
- **书架封面尺寸与阴影键**：`bookshelfCoverShadow` / `bookshelfGridCoverWidth` / `bookshelfListCoverWidth` 是 `bookshelfLayout` 的键，不是 `coverConfig` 的键。归 [书架对照表](BOOKSHELF.md) A2 块。
- **书籍详情页的封面背景与取色**（`bookInfoNetworkCoverBackground` / `bookInfoDefaultCoverBackground` / `bookInfoFollowCoverColor`）：键在 `themeConfig`，归 [深色模式对照表](ZIP-THEME.md) A20-A22。
- **详情页的换封面/搜封面入口**（`ChangeCoverSheet`、`PhotoDialog`）：归 [书架对照表](BOOKSHELF.md) B 块。
- **主题包里的封面图集导入导出**（`ThemePackageManager.kt` 的 `exportCoverAlbums`/`importCoverAlbums`）：它是主题包的组成，不是封面设置页本身；本表 B12 只记相册数据的来源，导入导出的完整盘点在 [深色模式对照表](ZIP-THEME.md) B 块。
- **`coverConfig` 之外的四类与封面有关的键**：`themeMode`（日夜）、`bookshelfLayout`（尺寸）、`themeConfig`（详情页背景）、`localBook`（封面 URI 落库）。

## 「ZIP 类别」列怎么读

照抄 [备份恢复](../BACKUP-RESTORE.md)「对照表的『ZIP 类别』列怎么读」的五条，并加本表的第五档：

1. **判据是「这一行要改代码时会动到哪个 ZIP 类别的键或文件」，不是「这个数据落在哪个类别里」。** 例：A4「默认封面」这一行改的是相册选择状态，但相册目录整个不进 ZIP，所以判 `不进备份` 而不是 `coverConfig`。
2. **`<类别名>`**（如 `coverConfig`）：这一行读写的是该类别的 `preferenceKeys` 里的键，或该类别打包的配置文件。备份/恢复该类别时这些键会跟着走。
3. **`A / B`**：这一行同时动到两个类别。本表没有跨两类的行（封面设置与书架布局的键分属两类且不交叉，详见「不覆盖」）。
4. **`—`**：这一行参与备份（键会出现在 `config.xml` 里），但**不受任何忽略开关控制**。依据 `help/storage/BackupConfig.kt:413 fun keyIsNotIgnore` 的 `else -> true`——不在任何 `dbIgnoreKeys`/`readPrefKeys`/`coverPrefKeys` 清单里的键，一律无条件导出。
5. **`不备份`**：连 `config.xml` 都进不去。依据 `data/local/preferences/LocalPreferences.kt:11`（`local_ui_status` 这个 DataStore 不参与备份）与 `help/storage/BackupConfig.kt:11-30 alwaysIgnoredPreferenceKeys`（24 项，含 `PreferKey.defaultCover` 与 `PreferKey.defaultCoverDark`）。
6. **`不进备份`（本表新增的第五档）**：连 ZIP 都进不去。前四档都不够用——`不备份` 的定义是「连 `config.xml` 都进不去」，而相册数据走的是 `externalFilesDir/cover_albums/albums.json` 这个独立目录：它不在 `help/storage/Backup.kt:156-220` 的任何 `dbIsNotIgnored` 分支里，`cover_albums` 也不在 `BackupConfig.kt:96-102` 的 19 类 `dbIgnoreKeys` 里，`Backup.kt:85-98` 的 `backupFileNames` 同样没有它。结论是**整个目录不进 ZIP**，与「进不进 `config.xml`」是两个层级的事，所以单列一档。凡是判 `不进备份` 的行，验收时不能靠「备份后恢复还在不在」来验，只能靠「备份包解压后有没有这个文件」。

## 本表与 [书架对照表](BOOKSHELF.md) 的边界

D 块（封面渲染）与 BOOKSHELF A1 有交叠：两边都会提到 `CoilBookCover` / `BookshelfCover` 的渲染行为。处置如下，**以后改哪边算数写在这里**：

- **BOOKSHELF A1 保留「封面在别的界面上长什么样」的行**，例如「书封渲染（含占位与灰底）」「书封阴影开关」「封面无障碍描述」——这些是书架界面自己的可见单元，BOOKSHELF 是它们的主表。

- **两边都提到同一个文件时，以「改了哪张表的行」为准**：改 `bookshelfCoverShadow`（书架布局键）→ 改 BOOKSHELF A2；改 `showShadow`（封面设置键）→ 改本表 D12。两者在本地恰好都作用到 `BookCover.ets:223` 的同一个 `.shadow(...)`，但传进来的是两个不同来源的参数，本表 D12 的差异说明里写清了这一点。
