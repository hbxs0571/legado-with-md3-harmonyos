# 已知问题与验收边界

更新：2026-10-28。以下只记录公开源码与 E 端验证状态能够支持的事实；不包含用户书名、阅读位置、设备地址、个人文件名或原始诊断材料。

## 尚未解决或尚未完成验证

1. **书架更新目录尚未做 E 端设备验收。** 入口与重算逻辑已接入源码，但未实测书架批量更新后的目录、进度迁移和重启状态。
2. **TXT 目录规则 CRUD/批量覆盖不完整。** 内置规则导入、JSON 导出再导入及 TXT 分卷场景已验证；编辑、删除、排序、批量启停/删除等完整组合仍需逐项覆盖。
3. **非空规则应用备份恢复未完成全往返。** 已核验合成 Android ZIP 的单条 `txtTocRule.json` 恢复并冷启动读回，以及空规则应用备份读回；未验证含非空规则的应用备份再恢复。
4. **API 12 真机兼容未验证。** 当前 E 端检查和公开副本构建不能替代 API 12 真机验收。
5. **设备自动化范围受限。** HMNextAuto `Driver.create` 返回 WinError 10054，当前使用 HDC 与本地 OCR；Android ADB shell/截屏曾超时。已测范围以记录的实际操作为准，不据此宣称更多页面通过。
6. **替换净化规则的超时字段没有限制运行时。** `timeoutMillisecond` 会随规则保存，但正文/标题替换仍使用同步正则；没有执行时限或中断机制。
7. **替换净化规则并发写入没有串行化。** 多个异步保存重叠时存在后写覆盖先写的风险；快速并发写入压力验证未完成。
8. **替换规则恢复提示仍需后续 UI 核验。** 新增、更新、跳过计数逻辑已接入，但完整提示样式与交互仍需设备检查。
9. **在线 URL 规则导入未接入。** 规则通过本地文件或用户提供的文本导入；应用没有通过 URL 获取规则的网络能力。

## 阅读记录已知缺口

- **跨午夜 HOS 日期边界未在 E 端核验。** N 端 API 26 结果不视为 E 端兼容证明。
- **扫描/修复提示尚未验收。** E 端未验证扫描 toast、异常行修复及派生明细/汇总的修复结果。
- **阅读字数恒为 0。** 会话、明细与汇总结构已接线，字数采集尚未实现。
- **书籍别名合并未迁移。** 目前没有按别名归并旧书名/作者记录的完整逻辑。
- **阅读标注/笔记仍为开发切片。** 共享页面代码随阅读记录接线进入源码，但不表示标注全流程已完成或通过设备验收。
- **Android ZIP 阅读记录不映射原生仓储。** `readRecord.json`、`readRecordDetail.json`、`readRecordSession.json` 作为兼容归档保留；恢复它们不等于导入原生三层阅读记录。

## 已纳入源码并完成部分验证

- 内置 TXT 目录规则 JSON 共 27 条，与上游对应文件字节一致；E 端导入后重启仍保留。
- JSON 规则导出并重新导入通过。临时自定义规则用于 TXT 导入，分卷识别、卷头折叠和阅读进度持久化通过；测试数据已清理。
- 书架记录保留 E 端 v13 分组/元数据；v14 `chapterVolumes`/`tocRule` 字段写入索引 28/29，并兼容 N 端旧布局中规则位于索引 27 的记录。
- 合成 Android ZIP 的单条 TXT 目录规则恢复后冷启动读回通过；空规则应用备份读回通过。非空规则应用备份恢复仍按上面的边界记录。
- TXT 规则的原生文件导出直接以字符串写入文件，避免空内容经字节数组写入触发 EINVAL；仍应按设备/文件选择器条件继续覆盖验证。
- 替换净化规则已有 ID 冲突处理、规则合并和空规则数组备份逻辑；这与 TXT 目录规则、阅读记录是独立模块，验证状态分别记录。
- 阅读记录旧 v1 迁移以会话键去重；先重建按日明细与按书汇总，随后再清理旧键。E 端只核验已报告的迁移/冷启动与控件状态，不外推为跨午夜、扫描修复或 API 12 全面通过。
- 阅读记录汇总视图按日明细分组，对齐上游 `groupedRecords = details.groupBy { it.date }`：跨午夜会话拆出的两段分别落到两天。时间线视图仍按会话起点日分组，与上游 `groupBy { it.startTime.toDateString() }` 一致。N 端 API 26 模拟器以 23:50→次日 00:20 的 30 分钟会话验证，拆为 28 日 10 分钟 + 29 日 20 分钟。
