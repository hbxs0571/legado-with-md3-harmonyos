# 鸿蒙迁移术语

**原生功能**：用户能在 HarmonyOS 页面完成对应操作，且需要保存的数据在重新启动后仍保持。页面外观或预览不等于功能完成。
_避免_：把页面壳或预览称为功能完成

**Android ZIP 数据映射**：把 Android 备份中语义明确且受支持的数据写入原生功能，并通过实际导入和结果核对验证。
_避免_：把原条目保存为兼容数据就称为已接入

**安全兼容**：识别、预览、忽略或原样保留未迁移的归档类别，不执行其中的规则，也不调用外部服务。
_避免_：把未迁移类别写成功能恢复

**当前模块**：功能队列中一次只处理的一个明确能力或一种 ZIP 数据类别，包含其直接页面、数据和受影响回归。
_避免_：把整个阶段或整站扫描当作当前模块

**模块验收**：对一个明确功能及其直接页面、数据和受影响行为进行验证，并记录已验和未验范围。

**候选能力**：已知但不在当前功能队列中的能力，不应描述为已排期或已接入。
_避免_：把候选能力写成下一步或已排期

**还原**：按 Android 对应页面的源码结构，在 ArkUI 中重建布局区域、控件、文案与图标，并使其可用。操作步骤见 [UI 还原流程](UI-RESTORE.md)。
_避免_：把画出一个相似页面称为还原

**校准**：把已还原的页面与原版置于同一内容、主题、字号和控制层状态下比对并消除差异。分整页同态对照与七项验收两级，不做逐像素门槛。
_避免_：用任意截图对比代替同态对照

**同态对照**：使用同一内容、章节锚点、主题/字号、控制层状态并记录视口与密度后的两端比较。
_避免_：只因同一本书就视为状态一致

**迁移**：把原版功能在 HarmonyOS 上以原生方式实现到可实际操作且数据可持久化，或按安全兼容规则明确归类为保留/忽略。
_避免_：把页面壳、预览或兼容占位数据称为迁移完成

**未迁移**：原版存在、当前尚未接入的能力。须保留图标、文字、行和必要目的页 UI 并明确标注，点击不伪造成功或实际执行。
_避免_：把未迁移项隐藏，或让按钮看起来可用

**占位**：为尚未接入的功能保留的结构与视觉位置，本身不含真实业务。不得用统一占位页代替原版完整 UI。
_避免_：用占位页冒充已还原页面

**弹层**：从页面浮出的临时界面层，包括底部面板、居中对话框与浮窗形态。Android 侧对应 `*Sheet*.kt` 与 `*Dialog*.kt`，基座为 `AppModalBottomSheet`。
_避免_：与页面导航混为一谈
