# 项目队列与工作边界

项目名称为 Legado with MD3 for HarmonyOS。目标是在 HarmonyOS 上以 ArkTS、ArkUI 和 Stage 模型实现本地阅读体验，并安全兼容部分 Android ZIP 备份数据。此文件记录机器无关的功能队列；当前公开进度见 PROGRESS.md。

## 功能队列

队列按用户使用顺序排列（2026-11-11 确定）：先让书架能用，再让阅读器能用，然后补朗读，其余三项按同样力度收口。每项「现在能做到什么、卡在这几处、算做完的判据」写在[功能交付清单](FEATURES.md)的对应章，本文件只记顺序与边界。

1. 书架：本地 TXT/EPUB 的导入、分组、搜索、详情与目录更新。在线来源与书单导入导出不在本段。
2. 阅读器：续读语义、分页与滚动两种模式、目录、书内搜索、替换净化、书签划线与笔记、TXT 目录规则验收、阅读配置全部生效。
3. 朗读（界面用语；技术上是 TTS）：系统语音合成与 HTTP TTS 音源，朗读设置页、听书界面与后台播放。
4. 阅读记录：日期边界、跨午夜切分、扫描修复、别名合并、三层持久化与热力图已可用；余下补三视图章号与私密书脱敏。
5. 外观：主题包、日夜模式、调色板、自定义配色、背景图、护眼、模糊与容器设置。
6. 备份与恢复：Android ZIP 28 类双向映射已完成；余下补旧版数据导入、系统目录选择与 WebDAV 的四个半占位开关。

队列表示实施顺序，不表示对应能力都从零开始。领取某块时应保留已有行为，明确区分原生功能、Android ZIP 数据映射与安全归档。每个模块都需说明页面入口、真实行为、未迁移项和验证结果；跨模块改动应有明确调用方，不因清空路由清单而扩大范围。

## 页面与行为

以 Android 对应页面、直接组件、文案与图标为结构参考。当前模块覆盖的页面应具备对应的布局区域、可操作控件、滚动、状态反馈和正确返回关系。未迁移的动作须显示真实状态，不能以预览代替已接入功能。

验收重点是页面可达、结构完整、内容可读、操作有效、返回正确和状态真实。只有源码无法确定布局、行为存在疑点或出现回归时才进行针对性截图比对；不以逐像素一致作为默认门槛。

## 在线服务（已纳入范围）

在线书源抓取、RSS 拉取、TTS 服务、WebDAV 属于本项目范围之内，四项进度不同：**WebDAV 已落地**（上传、下载、远端列表与凭据设置，走 `rcp`，见 `entry/src/main/ets/lib/WebDav.ets`，并入功能队列第 6 项）；**朗读服务（TTS）已排期**（功能队列第 3 项，本地目前零音频能力，系统侧可用 `@kit.CoreSpeechKit`）；**在线书源抓取与 RSS 拉取仍未排期**，页面上相关入口仍是未迁移占位。

纳入范围只表示「要做」，不表示「已经做了」。书源排在 RSS 之前，因为书源是阅读链路的直接上游；RSS 相对独立，可最后做。

### 落地前提（四项共用）

- **网络层**：`rcp`（RemoteCommunicationKit）已引入并落地在 `lib/WebDav.ets`，但它只覆盖 WebDAV 动词，书源/RSS 需要的通用 HTTP（重试、并发上限、Cookie）仍未建，`@ohos.net.http` 也可以直接用于这两项。
- **凭据按不可信数据对待**：备份里带的脚本与凭据照旧不执行、不连接外部服务；用户输入的账号密码要落到本机凭据存储，不进备份明文。WebDAV 账号密码目前明文存 preferences，属已知限制。
- **API 基线不变**：四项都可以在 `5.0.0(12)` 上做，不需要抬 `compatibleSdkVersion`。
- **每项都要有独立的收发证明**：能抓一本书的目录与正文、能播一段 TTS、能拉到一篇文章、能备份并还原一次，才算接完。

## 范围之外

AI 在线服务、云同步以及额外设备形态适配均不因出现在页面或备份归档中而视为已实现。备份中的脚本与凭据按不可信数据处理，不执行，也不连接外部服务。
