# 项目队列与工作边界

项目名称为 Legado with MD3 for HarmonyOS。目标是在 HarmonyOS 上以 ArkTS、ArkUI 和 Stage 模型实现本地阅读体验，并安全兼容部分 Android ZIP 备份数据。此文件记录机器无关的功能队列；当前公开进度见 PROGRESS.md。

## 功能队列

队列表示实施顺序，不表示对应能力都从零开始。领取模块时应保留已有行为，明确区分原生功能、Android ZIP 数据映射与安全归档。

1. 收口本地阅读链路：续读语义、无目录 TXT 分段与受影响的阅读配置。
2. 完整阅读记录：日期、明细、会话和重启后状态。
3. 书签、划线与笔记：创建、查看、编辑、定位和持久化，并分别记录支持范围。
4. 收口 TXT 目录规则验收：书架更新目录设备验证、完整 CRUD/批量操作覆盖、非空规则应用备份恢复。
5. 替换净化规则：规则管理、启停、顺序和阅读时应用。
6. Android ZIP 数据映射：逐类映射有明确等价语义的数据，再核对安全保留或忽略类别。

每个模块都需说明页面入口、真实行为、未迁移项和验证结果。跨模块改动应有明确调用方，不因清空路由清单而扩大范围。

## 页面与行为

以 Android 对应页面、直接组件、文案与图标为结构参考。当前模块覆盖的页面应具备对应的布局区域、可操作控件、滚动、状态反馈和正确返回关系。未迁移的动作须显示真实状态，不能以预览代替已接入功能。

验收重点是页面可达、结构完整、内容可读、操作有效、返回正确和状态真实。只有源码无法确定布局、行为存在疑点或出现回归时才进行针对性截图比对；不以逐像素一致作为默认门槛。

## 范围之外

在线书源抓取、RSS 拉取、TTS 服务、WebDAV、AI 在线服务、云同步以及额外设备形态适配均不因出现在页面或备份归档中而视为已实现。备份中的脚本与凭据按不可信数据处理，不执行，也不连接外部服务。

功能状态与设备验证结果请查看 [进度摘要](PROGRESS.md) 和 [验证记录](VALIDATION.md)。
