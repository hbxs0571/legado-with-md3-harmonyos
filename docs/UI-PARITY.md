# UI 结构与可用性验收

以原 Android 项目的 Screen、Route、直接组件、文案和图标作为结构参考。当前模块涉及的页面需要有对应的布局区域、可读内容、可操作控件、滚动与选中状态、弹层和返回关系。

五个主导航（首页、书架、发现、订阅、我的）和已注册路由作为查漏索引，不自动成为逐页复刻的阻塞清单。已进入当前功能模块的页面必须不妨碍真实操作；页面前进/返回、弹层开合、按下反馈及阅读控制层应可用。路由清单只是查漏索引，**当前模块涉及的页面仍按完整页面交付**，不得以「不在清单内」为由只做单张卡片或单个功能。

每个模块按七项检查：入口可达、页面结构完整、文字可读、文案与图标来源正确、操作有效、返回正确、状态真实。动效只在影响触控、反馈或返回时作为阻塞问题处理。未迁移功能应明确标记；仅有视觉控件或动画不代表数据已保存或服务已启动。还原步骤见 [UI 还原流程](UI-RESTORE.md)。

截图只用于源码无法判断布局、交互有疑点或发现视觉回退的情况。这里的“截图核对”指人工视觉比对；模拟器 OCR 导航所需的临时取像不作为逐页视觉验收，也不在成功路径展示给用户。构建通过不能代替设备交互检查；设备不可用时明确记录未验。公开仓库不包含用户数据截图或诊断布局树。

**像素口径以本条为唯一标准**：不做逐像素门槛，但七项验收与整页同态对照不可省。不要求逐张截图像素级 1:1，也不以像素级差异阻断推进；同时不得据此省略验收项或跳过同态对照。
