> **本流程已于 r258 移交后失效，仅作历史记录保留。** E 机在 2026-10-28 r258 检查点停止新增功能，后续开发由 N 端单机承担并直推 `main`。下面描述的「N 机归档、E 机复核、经功能分支提交」流程不再执行；不要据此创建私人归档、不要另开待合并的功能分支，也不要按第 13–17 行等待 E 机复核。

本文件供另一台电脑从公开 HarmonyOS 仓库读取。两台电脑的本地磁盘互不可见；N 机只在自己的电脑上处理原始文档，E 机不读取 N 机私人归档。

## N 机先做

1. 暂停当前写入并保存模块检查点。先核对当前仓库、分支、远端和工作区状态；不要在有未提交改动时直接 `pull`，不要把 Android 原项目仓库当作 HarmonyOS 远端。
2. 用 `git ls-files --others --exclude-standard -- docs` 重新统计未跟踪文档。只把这份清单中的文件按原相对路径复制到**本机 Git 仓库之外**的私人归档，生成相对路径、字节数和 SHA-256 清单；另查是否有被忽略但需要保留的本机证据。已跟踪但修改过的文件单独保存补丁或临时分支。
3. 核对归档数量、逐项哈希和抽样可读性。当前模块完成检查点、共享文档入口可用后，才从工作区移出已核验的未跟踪文件。删除或移动前确认来源和归档的绝对路径均在预期目录内。不要移动整个 `docs/`，不要运行 `git clean -fd`，不要删除已跟踪文件。
4. 在 N 机本地把私人归档与**最新公开 `main`** 的同主题文档比较。先看相对路径和哈希，再逐段检查不同内容；同日修改时间不代表同一版本或优先版本。给私人清单中的每个文件标记“重复、已提炼进功能分支、本机证据、待复核”之一。
5. 只把与当前功能相关、去除私人书名、设备/机器路径、备份细节和截图的新增事实写入功能分支。每个模块单独构建和验收，并提交简短的模块验收摘要。N 机本地 `CURRENT.md` 不上传，也不修改 E 机的续接记录。

## 交给 E 机复核的内容

通过功能分支或 PR 提交：模块名称、基线提交、修改文件、脱敏的行为差异、验证结果、未验证项，以及私人清单各处理类别的**数量汇总**。不要上传原始归档、含私人文件名的完整清单、截图或用户样本。E 机对照自身活文档和公开基线审查新增事实，再合并共用项目书、索引、术语和模块状态；同一事实只保留一处权威记录。

如某个差异必须查看原始材料才能判定，先停在“待复核”，再另选私人传输方式；公开仓库不能充当私人文件交换区。N 机完成本地归档和比对、E 机完成分支复核之前，不把“双方文档已同步”标为完成。
