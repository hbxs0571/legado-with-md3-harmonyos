# 当前进度

更新：2026-10-28，对应 E 端 r241 稳定检查点的阅读记录整合公开快照。此处不列本机续接记录、用户书名、阅读时刻、设备地址或备份内容。

## 阅读记录整合与 E 端核验

- 同步三层阅读记录模型与仓储：阅读会话、按日明细、按书汇总；`Index`、阅读记录页及阅读器会话生命周期已接线。
- 旧 `ReadTimeRepository` 的 v1 本地记录迁移到会话层；迁移后重建派生明细/汇总，再清理旧键；重复冷启动不会重复迁入已存在会话。
- E 端 r241 HAP 构建、覆盖安装与冷启动通过。旧记录迁移后重启未重复；新 TXT 阅读会话已写入记录；取消清空确认未删除记录，阅读记录开关恢复启用后状态保留。
- E 端检查后，原有书架条目与阅读进度仍保留。公开摘要不列书名、时间或原始记录数。
- 共享 `Index`/`ProfileSubPages` 还带有开发中的标注/笔记代码，以满足页面接线依赖；它们仍在开发和设备验证中，本次不将其标记为已完成。
- 当前 Android ZIP 中的 `readRecord.json`、`readRecordDetail.json`、`readRecordSession.json` 仍作兼容归档，不映射到 HarmonyOS 原生三层仓储。

## 尚未完成的验收与功能缺口

- 跨午夜后的 HOS 本地日界与持久化尚未在 E 端验证。N 端 API 26 测试仅属于 N 端，不作为 E 端证据。
- E 端未验证扫描提示、异常行修复及派生数据修复流程；设备自动化范围不足以证明这些操作通过。
- 阅读字数目前恒为 0；按书名/作者别名合并尚未迁移。
- 阅读记录统计与修复操作仍需更广覆盖；书签、划线、笔记共享切片没有完成全流程验收。
- API 12 真机兼容尚未验证。
- TXT 目录规则、替换净化、阅读器页面和 Android ZIP 仍有各自待验项，分别见[模块状态](MODULE-STATUS.md)和[已知问题](KNOWN-ISSUES.md)。
